# Add authorization state machine, stress tests, and governance safeguards for LedgerLens score

## Summary

Implement comprehensive security enhancements to the LedgerLens score contract's authorization and governance model, including explicit signer state transitions, high-cardinality stress testing, and quorum downgrade protections.

## Changes

- **Explicit Signer State Machine** (#691): Replace implicit signer transition assumptions with explicit `pending`, `active`, `superseded`, and `revoked` states. Includes deterministic validation of state transitions and tests proving invalid skips/replays fail.

- **High-Cardinality Stress Tests** (#690): Add stress tests generating many wallet/pair combinations to validate stable counts/history and record resource budgets for worst-case scenarios. Tests assert no accidental key collisions, ordering dependence, or unexpected resource blowups.

- **Quorum Downgrade Protections** (#692): Prevent emergency paths from silently requiring weaker authorization than routine governance paths. Every emergency action has explicit signer threshold policy with tests proving downgrade attempts fail.

- **Bounded Signer Churn Tests** (#693): Implement tests exercising signer additions, removals, tier changes, and threshold updates while governance proposals are pending. Tests prove pending decisions remain attributable to the original signer set or are invalidated deterministically.

## Affected Areas

- `contracts/ledgerlens-score/src/parameter_governance.rs`: Signer state machine and governance logic
- `contracts/ledgerlens-score/src/lib.rs`: Authorization checks and emergency actions
- `contracts/ledgerlens-score/src/types.rs`: Score ingestion and validation

## Acceptance Criteria Met

✓ State transitions documented with comprehensive test coverage
✓ Stress tests validate resource bounds and worst-case behavior
✓ Emergency actions protected by explicit quorum policies
✓ Pending decision attribution verified under signer churn
✓ Public ABI, event, error, and storage compatibility impacts documented
✓ Resource usage bounded and benchmarked
✓ No fail-closed risk-gate semantics or authorization checks weakened

## Breaking Changes

None. All changes maintain backward compatibility with existing ABI, events, and storage layout. See compatibility notes in implementation PRs for detailed impact analysis.
