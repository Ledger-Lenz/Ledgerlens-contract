# Production Acceptance and Readiness

This document defines the release gate for activating LedgerLens contract
deployments in production. It is intentionally operational: every required
claim must point to executable evidence, a named owner, and a stable report ID.

## PR Checklist

Entry points affected by this issue:

- `scripts/production-acceptance.sh`
- `scripts/testnet-canary-rehearsal.sh`
- `.github/workflows/ci.yml`
- `docs/production-acceptance.md`
- `docs/reports/production-readiness-report.md` generated by the suite
- `docs/reports/testnet-canary-rehearsal.md` generated by a testnet drill

Contract entry points exercised by the canary:

- `get_admin`
- `get_service`
- `is_score_stale`
- `submit_score`
- `pause`
- `unpause`
- rollback preparation through `propose_upgrade` evidence only
- signer recovery preparation through `set_service` evidence only

Storage keys, events, and errors:

- No new persistent or instance storage keys.
- No public ABI change.
- No new event topics.
- No new `Error` discriminants.
- Expected error paths include `Unauthorized`, `ContractPaused`, and existing
  validation failures from malformed score submission inputs.

Tests and automation:

- `cargo fmt --all -- --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test --workspace`
- `cargo test -p replay`
- `cargo build --target wasm32-unknown-unknown --release -p ledgerlens-score --locked`
- `scripts/production-acceptance.sh`
- `scripts/testnet-canary-rehearsal.sh --network <isolated-alias> ...`

## Readiness Criteria

Production activation is blocked unless every item below is complete.

| Criterion | Owner | Evidence | Alert threshold | Decision authority |
| --- | --- | --- | --- | --- |
| Native tests, formatting, strict clippy, replay, and locked WASM build pass | Contract maintainer | `docs/reports/production-readiness-report.md` | Any failed step | Maintainer reviewer |
| Error discriminants and storage layout remain compatible | Contract maintainer | CI error-discriminant job plus this checklist | Any removed, renamed, or renumbered discriminant | Maintainer reviewer |
| WASM artifact hash and byte size are recorded | Release operator | readiness report artifact section | Missing hash or unexplained size growth | Release captain |
| Testnet canary covers authorization, pause, stale-state read, partial failure, rollback preparation, signer recovery, and reconciliation | Release operator | `docs/reports/testnet-canary-rehearsal.md` | Any scenario failure or missing log | Release captain |
| Backup/restore or rollback drill has integrity reconciliation | Release operator | canary report plus previous WASM hash/state digest | Missing digest or unverifiable rollback target | Release captain |
| Runbook validated by a non-author reviewer | Independent reviewer | reviewer field in canary report and PR approval | Reviewer did not run or inspect evidence | Maintainer reviewer |
| Monitoring thresholds configured | On-call operator | PR design section or deployment ticket | Missing threshold for any critical signal | On-call lead |

Critical monitoring signals:

- `upgrade_proposed` event: page immediately if the hash does not match a
  reviewed release artifact, or if no deployment ticket references the proposal.
- `upgrade_executed` event: page if execution occurs before the approved window.
- `pr_pause` or global pause state: page on unexpected pause or unpause.
- Score submission failure rate: page if accepted submissions fall below the
  service SLO for two consecutive windows.
- Stale scores: page if any production asset-pair feed exceeds the configured
  staleness window.
- Replay drift: block deployment if replay output changes without a PR note
  explaining the protected invariant.

## Trust Assumptions

The release process assumes:

- Admin and service signing keys are controlled by separate operational roles.
- Testnet canary networks are isolated from production configuration and use
  non-production keys.
- A release WASM hash is reviewed before proposal and can be rebuilt from the
  pinned toolchain and `Cargo.lock`.
- Off-chain score methodology is outside this repository; this gate verifies
  the contract, tooling, and operational controls around score publication.

## Authorization Boundaries

Score writes remain limited to the configured service path or service signer
threshold. Administrative controls, including pause, unpause, service rotation,
parameter governance, and upgrade governance, remain admin-only. Read-only
queries used by integrators must remain side-effect free; this issue does not
add writes to read paths.

## State Transitions

The acceptance suite validates these operational states:

- Normal: reads work, submissions are accepted only from authorized signers.
- Stale read: stale-score diagnosis can be queried without writing.
- Rejected unauthorized write: unauthorized submission fails closed.
- Paused: score submission is blocked while pause is active.
- Restored: unpause returns the contract to its pre-drill control state.
- Rollback prepared: the previous reviewed WASM hash is identified before
  production activation.
- Reconciled: admin and service addresses are re-read after the drill.

## Failure Modes and Recovery

| Failure mode | Detection | Recovery |
| --- | --- | --- |
| Unauthorized caller attempts to write | canary rejected write and production auth alerts | no state change expected; investigate caller |
| Service signer unavailable | submission SLO breach and signer-loss drill evidence | rotate service or use configured threshold signer set |
| Contract paused unexpectedly | pause event or readback | verify authority, diagnose reason, unpause only after incident lead approval |
| Bad WASM proposed | hash mismatch alert during timelock | veto proposal before execution |
| Bad WASM executed | post-upgrade smoke failure | pause if needed, propose previous reviewed WASM or hotfix |
| Stale or replayed data | staleness monitor, replay harness, duplicate/reordered test failures | stop submissions, replay from last signed checkpoint, reconcile score counts |
| Partial canary failure | failed scenario log | keep production activation blocked until rerun passes |

## Resource Bounds

The automated readiness report records the release WASM byte size and SHA-256.
Worst-case CPU, memory, ledger reads/writes, event bytes, and encoded input size
must be summarized in the PR using either measured Soroban diagnostics or a
tight bound from the constants and tests that cover the changed surface. For
this issue, the contract surface is unchanged; the relevant bound is that the
new scripts do not alter on-chain execution.

## How To Run

Generate the local acceptance report:

```bash
scripts/production-acceptance.sh
```

Generate and detach-sign the report with GPG:

```bash
READY_SIGNER_NAME="release-operator" \
READY_DECISION_AUTHORITY="release-captain" \
READY_STATUS="APPROVED_FOR_TESTNET_CANARY" \
READY_SIGNED_AT="$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
READY_GPG_KEY="<key-id>" \
scripts/production-acceptance.sh
```

Run a dry rehearsal without touching a network:

```bash
scripts/testnet-canary-rehearsal.sh \
  --dry-run \
  --network isolated-testnet \
  --contract CXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX \
  --operator deployer \
  --admin GXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX \
  --service GYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY \
  --asset-pair XLM_USDC \
  --reviewer reviewer-name
```

Run the live rehearsal only against a disposable Stellar network alias or
testnet deployment created for this release candidate. Attach the generated
report path to `CANARY_REHEARSAL_REPORT` before signing the readiness report.
